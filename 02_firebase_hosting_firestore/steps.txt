PRACTICAL 2 — FIREBASE HOSTING + CLOUD FIRESTORE CRUD
Scenario: Student Management
Files: public/index.html, firebase.json

A. CREATE PROJECT AND WEB APP
1. Open https://console.firebase.google.com/ and sign in.
2. Click Create a project or select your existing project.
3. Finish the project creation wizard.
4. Open Project settings (gear icon) -> General.
5. Under Your apps, click Web (</>) to register a web app.
6. Give it a nickname and register the app. Hosting can be enabled now or later.
7. Copy the Firebase configuration object. In public/index.html, replace:
   YOUR_API_KEY
   YOUR_PROJECT_ID
   YOUR_MESSAGING_SENDER_ID
   YOUR_APP_ID
   Ensure authDomain and storageBucket also match the values from your own config.
8. Save the file.

B. CREATE FIRESTORE
1. In Firebase Console, open Build -> Firestore Database.
2. Click Create database.
3. Choose a region/location and create it.
4. This app uses collection name students. Firestore creates it after the first successful Add Student operation.
5. Security rules:
   - If using rules that require request.auth != null, this starter needs Firebase Authentication/sign-in code first.
   - For a short practical demo, use a dedicated test project and temporary rules only if your instructor permits it. Do not leave public read/write rules enabled in a real project.
   - After the practical, restore appropriate rules.

C. INSTALL FIREBASE CLI
1. Install Node.js LTS from https://nodejs.org/ if not installed.
2. Open CMD/VS Code terminal and run:
   npm install -g firebase-tools
3. Sign in:
   firebase login
4. Check:
   firebase --version

D. INITIALIZE HOSTING
1. Open a terminal inside 02_firebase_hosting_firestore.
2. Confirm this folder contains firebase.json and the public folder.
3. Run:
   firebase projects:list
   Make sure your Firebase project appears.
4. If you need to link the folder to your project, run:
   firebase use --add
   Select the correct project and assign an alias such as default.
   This creates .firebaserc. If already linked, do not repeat this.
5. Confirm firebase.json uses "public": "public".
6. Confirm your app is at public/index.html.

E. LOCAL PREVIEW
1. Run:
   firebase emulators:start --only hosting
2. Open the local URL printed in the terminal.
3. If the Hosting emulator is not configured yet, run:
   firebase init emulators
   Select Hosting Emulator and accept a free port.
   Then run the command again.
4. Test adding/editing/deleting. A local Hosting emulator does not automatically emulate Firestore; the page still calls your real Firestore project unless you configure a Firestore emulator too.

F. DEPLOY
1. Run from this folder:
   firebase deploy --only hosting
2. Wait for deployment to finish.
3. Open the Hosting URL printed by the CLI.
4. Test adding, viewing, editing and deleting a student.
5. In Firebase Console -> Firestore Database -> Data, confirm the students collection contains your records.

G. COMMON ERRORS
- firebase not recognized: close/reopen terminal after npm global install; check npm global PATH.
- Not logged in: run firebase login.
- Wrong project: run firebase projects:list and firebase use --add.
- 404 after deployment: ensure public/index.html exists and firebase.json public is "public".
- Firebase config/invalid API key: copy config values exactly from Project settings.
- Missing/insufficient permissions: inspect Firestore rules; the starter has no login, so authenticated-only rules will deny it.
- App loads but no data: check browser DevTools Console and Firestore rules.
- Do not publish private service-account keys in frontend code.

CRUD mapping:
Create = addDoc; Read = getDocs; Update = updateDoc; Delete = deleteDoc.
